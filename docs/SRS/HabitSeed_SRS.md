## 1. 产品概述

### 1.1 产品定位

HabitSeed 是一款面向初中生的习惯养成移动应用。用户通过"种下一颗种子"来绑定一个希望坚持的习惯，每天完成习惯后"浇水"推动植物生长；连续坚持至生长周期结束即可收获开花成果。应用采用损失厌恶机制：忘记浇水会导致植物停止生长，严重时枯萎；提供复活机制作为挫败缓冲；以游戏化收集提供成就感。

信任模型说明：浇水动作由用户自主确认完成习惯，系统不校验习惯实际执行情况；建议家长与孩子建立使用约定，外部引导自律。

### 1.2 目标用户

- 主要用户：初中生（12–15 岁）
- 次要用户：家长（可查看孩子进度，但不强制参与）

### 1.3 核心价值

| 价值 | 说明 |
| --- | --- |
| 降低启动门槛 | 选种子 → 命名习惯 → 开始，3 步完成 |
| 短时参与 | 每次浇水操作 1 分钟内完成 |
| 持续动力 | 枯萎惩罚 + 复活缓冲 + 成就收集 + 最多 3 株植物并行 |
| 零社交压力 | 纯单机，不与他人比较 |

### 1.4 平台与技术

| 项 | 方案 |
| --- | --- |
| 平台 | Android (API21+)、iOS (13.0+) Flutter 跨平台；风险备注：iOS 生成 IPA 安装包需要苹果开发者账号；若无账号则仅产出 Android 包，iOS 安装包延后 |
| 语言 | Dart |
| 状态管理 | Riverpod |
| 本地存储 | Hive（动态业务数据）+ JSON 文件（静态配置） |
| 图片 | MVP 全部生长阶段图片打包进 assets；远程图片增量同步架构保留，MVP 不启用 |
| 网络 | 后期通过 API 获取种子 / 成就数据；MVP 完全使用本地 JSON |

响应式适配：一套代码同时适配手机与平板，布局依据应用窗口可用宽度自适应，详见第 9 章。

## 2. 功能需求

### 2.1 种子商店（Seed Shop）

- 应用首次启动时，从本地 assets/seeds.json 加载种子配置数据。
- 商店按类别分页签展示种子：草本 / 花卉 / 果蔬 / 树木 / 幻境。
- 每个种子卡片展示：名称、稀有度标签、生长周期天数、停长阈值、枯萎阈值、最终形态图片。
- 稀有度分级与生长周期对应关系：

| 稀有度 | 周期区间 | 颜色标识 |
| --- | --- | --- |
| 寻常 | 7–30 天 | 绿色 |
| 清雅 | 31–60 天 | 蓝色 |
| 珍奇 | 61–120 天 | 紫色 |
| 史诗 | 121–200 天 | 橙色 |
| 传说 | 201–300 天 | 红色 |

- 容错阈值规则：连续 N 天未浇水→停止生长；连续 M 天未浇水→枯萎；最短停长间隔≥3 天，最短枯萎间隔≥5 天，最长枯萎间隔≤10 天；具体阈值在种子配置中定义，与生长周期正相关。
- 商店列表展示种子最终形态图片。
- 用户最多可同时种植 3 颗种子；花园已满时，"种植"按钮置灰并提示"花园已满，收获或铲除植物后可种植新种子"。
- 无种子背包、无种子解锁 / 消耗逻辑：商店全部种子均可直接选择种植；难度由生长周期、容错阈值体现，由用户自行权衡挑战。
- 过滤能力：支持按种子类别过滤（草本/花卉/果蔬/树木/幻境，支持【全选】）；支持按稀有度过滤（寻常/清雅/珍奇/史诗/传说，支持【全选】）；多条件为交集关系。
- 排序能力：生长周期升序 / 降序；默认排序为生长周期升序。
- UI 交互：商店顶部放置过滤面板（类别多选、稀有度多选、排序下拉），过滤条件变更实时刷新种子卡片列表。

### 2.2 种植习惯（Planting）

- 用户在商店选择一颗种子后进入种植流程：①输入习惯名称；②确认种植。
- 确认后系统：在 Hive 中创建 PlantedSeed 记录；返回花园首页。
- 修改：MVP 图片全部来自 assets，不再复制图片到本地缓存目录，meta.json 架构保留供后期迭代。
- 种植后花园首页显示：当前阶段图片、习惯名称、已坚持天数、距停长 / 枯萎剩余天数。

### 2.3 花园首页（Garden Home）

- 以网格 / 列表形式展示当前种植的所有植物（最多 3 个）。
- 每张卡片显示：当前阶段图片、习惯名称、稀有度标签、生长进度条、状态指示器（正常🟢 / 停止🟡 / 枯萎💀）、距停长或枯萎剩余天数。
- 每天每个植物只能浇水 1 次。
- 浇水操作：点击卡片→浇水页→点击"浇水"→播放动画→进度 + 1 天，更新 lastWateredDate，重置连续未浇水计数器。
- 浇水为信任模式，系统不校验习惯真实完成情况。
- 浇水后可选择写一句备注（非强制），记录在浇水日志中。
- 植物状态判定（每次打开 App 或浇水后触发）：
  - `today - lastWateredDate < stopThreshold` → 正常生长🟢（若前一天刚浇过水，不显示"距停长还剩 N 天"提示）
  - `counter == stopThreshold` → 停止生长（黄叶，补浇水可恢复）🟡
  - `counter >= deadThreshold` → 枯萎死亡💀
- 停止生长的植物浇水后恢复正常，已积累天数保留；枯萎植物默认不可恢复，只能铲除进入纪念花园；复活机制见 2.3.1。
- 花园首页增加按钮：【保存花园截图】，将当前花园渲染为图片保存至系统相册，需要相册权限；仅本地保存，无网络分享。
- UI 指示器：全局显示复活机会状态：复活机会：可用 / 无。

#### 2.3.1 复活机制

- 触发条件：任意一颗种子完整走完生长周期成功开花移入成就花园，获得 1 次复活机会；复活机会不累积；已有复活机会时再次开花不会新增复活机会。
- 操作入口：纪念花园内，针对枯萎植物点击复活按钮；无复活机会时按钮置灰不可点击。
- 复活后状态：①植物回到 stopped（停止生长）状态；②恢复该枯萎植物原有历史坚持天数 totalWaterDays、原有 plantedDate；③更新 lastWateredDate = 当前时间；④从纪念花园移除，回到花园首页继续浇水生长。
- 约束规则：取消单株植物复活次数限制。只要用户手上持有可用复活机会，同一株枯萎植物可以被反复复活；复活机会消耗后，需要再成功培育开花一株植物重新获取复活机会。
- 产品风险备注：理论上可反复复活同一株植物，但每一次复活都必须以成功培育另一株完整开花作为代价，不存在无成本兜底。

### 2.4 成就花园（Achievement Garden）

- 种子达到生长周期全部天数（成功开花）后状态置为 harvested，自动"移入"成就花园；harvested 记录保留在 planted_seeds Box（不另设 Box），成就花园及导入导出快照按状态过滤读取（4.1）；开花成功时产出复活机会（如当前无复活机会）。
- 以网格展示已开花植物：种子名称、稀有度、习惯名称、坚持总天数、开花日期、最终形态图片。
- 成就数据从本地 assets/achievements.json 加载（后期切 API）。
- 系统根据种植记录自动判定解锁成就（如"初次绽放""累计 10 颗""传说级培育"等）。

### 2.5 纪念花园（Memorial Garden）

- 用户手动铲除枯萎植物后进入纪念花园。
- 以列表展示：种子名称、习惯名称、曾坚持天数、枯萎日期、"墓碑"图标。
- 纪念花园支持复活操作（有复活机会时）；复活后该记录从纪念花园移除，回到花园首页。
- 纪念花园不提供恢复以外的复原功能。

### 2.6 图片同步（Image Sync）

- MVP 阶段：全部生长阶段图片内置在 assets，不执行远程下载、增量同步；meta.json 数据结构完整保留用于未来迭代。
- 后期迭代：选定种子后将该种子所有生长阶段图片保存到本地缓存目录；维护 meta.json 记录图片 lastModified 时间戳；App 启动后台比对更新，增量下载变更图片。

### 2.7 后台数据切换（架构预留）

- 种子 / 成就数据通过 Repository 模式访问，底层数据源可在"本地 JSON"与"远程 API"间切换，不改动 UI 层代码。
- MVP 阶段仅实现本地 JSON 数据源。
- 后期接入远程 API 需支持：GET /api/seeds、GET /api/seeds/{id}/images/meta、GET /api/seeds/{id}/images、GET /api/achievements。

### 2.8 系统时间篡改防护

- 无法做到 100% 防作弊，采用轻量检测 + 提示，不破坏用户数据。
- 在 app_settings 持久保存 lastAppAliveTs：每次 App 切回前台 (resume) 记录当前时间戳 millisecondsSinceEpoch。
- App 每次前台恢复：对比当前时间戳与 lastAppAliveTs。当前时间戳 < lastAppAliveTs 判定时间回退异常；差值 > 48 小时标记时间可疑。
- 检测异常：弹窗提示"检测到系统时间发生变更，花园生长状态可能出现异常，请把系统时间设置为自动确定。"；设置全局标记 isTimeTampered=true，花园首页顶部常驻弱提示；App 重启且时间恢复正常后清除标记。
- 业务计算仍然基于系统时间；不自动回滚 / 修改用户业务数据，避免误判损坏正常进度。

### 2.9 通知‑浇水提醒

- 设置页面开关「浇水提醒」，默认关闭；开启开关时才申请系统通知权限；用户拒绝权限，则开关自动置为关闭。
- 支持自定义提醒时刻（小时 + 分钟）；UI 限制可选时间范围 08:00–21:00，规避深夜打扰。
- 仅当花园中存在 growing / stopped 状态植物才触发提醒；全部植物为 dead / harvested 不推送。
- Android：增加提示文字"为保证提醒正常，请允许 App 后台活动"，适配国内厂商后台限制。iOS 遵循系统通知权限策略。

### 2.10 设置页面 /settings

- 设置页面包含：浇水提醒（开关、自定义提醒时间）、数据导出、数据导入、清除全部应用数据（二次确认）、关于页面（应用版本号）。
- 暂不实现主题切换功能。

#### 2.10.1 数据导入导出细化

**导出：**

- 点击导出，二次确认；快照包含 planted_seeds、water_logs、achievement_records、memorial_plants、app_settings；不导出图片（图片始终在 assets 内）。
- 文件命名：habit_seed_backup_yyyyMMdd.json。
- Android：保存至下载目录；iOS：调用系统分享面板，用户保存到"文件"App。

**导入：**

- 点击恢复，强二次确认：恢复将覆盖当前所有花园数据，是否继续？
- 使用 file_picker 选择本地 JSON 文件；做基础字段校验；非法文件提示"备份文件无效"。
- 校验通过清空对应 Hive Box，写入备份数据；完成提示用户重启 App。
- UI 风险提示：仅支持本 App 导出备份；手动修改 JSON 文件会造成 App 异常。

### 2.11 响应式布局（跨设备）

- 使用同一套代码运行于手机与平板，不针对设备型号单独维护 UI。
- 布局以应用窗口可用宽度（dp）为判断依据（通过 LayoutBuilder / MediaQuery），禁止按设备类型或屏幕方向硬编码两套整页 UI。
- 断点定义：

| 宽度区间（dp） | 形态 | 布局规则 |
| --- | --- | --- |
| < 600 | 手机 | 底部 3‑Tab + 单列卡片 |
| 600–839 | 小平板 / 横屏手机 | 2 列网格 |
| >= 840 | 平板 | 左侧 Navigation Rail + 多列网格，弹窗类页面用居中浮层 |

- 网格列数随宽度连续变化，而非在整页间硬切换。
- 浇水页、开花庆祝、种植习惯等弹窗 / 卡片页面使用 ConstrainedBox 限制最大宽度，避免宽屏下过度拉伸。

### 2.12 横竖屏支持

- 不在 main() 锁死方向，系统旋转可触发 UI 重建。
- 平板：支持横屏与竖屏，旋转时按 2.11 规则自动重排。
- 手机（MVP 取舍）：可限定竖屏，减少 MVP 工作量；后续放开双方向不影响架构。
- 配置变更（旋转、多窗口、折叠屏）重建时，通过 Hive + Riverpod 保持数据一致；滚动位置、动画状态按需恢复。
- 禁止因锁方向导致大屏 / 折叠屏出现黑边。

## 4. 数据设计

### 4.1 Hive Box 设计

| Box 名 | 存储内容 | 键值类型 |
| --- | --- | --- |
| planted_seeds | 全部种植档案：当前种植（growing/stopped/dead）与已收获（harvested）。harvested 记录供成就花园过滤展示（2.4） | key=String(id), value=PlantedSeed |
| water_logs | 浇水记录 | key=autoId, value=WaterLog |
| achievement_records | 已解锁成就 | key=String(achievementId), value=AchievementRecord |
| memorial_plants | 纪念花园植物 | key=String(id), value=MemorialPlant |
| app_settings | 应用设置、系统时间检测状态、复活机会计数等 | key=String, value=dynamic |

备注：已开花（harvested）记录不另设 Box，保留于 planted_seeds，供成就花园按状态过滤读取（2.4）；复活机会计数、系统时间篡改标记等动态状态存于 app_settings。

### 4.2 核心模型

```dart
class PlantedSeed {
  String id;
  String seedId;           // 关联种子配置
  String habitName;
  DateTime plantedDate;
  DateTime lastWateredDate;
  int totalWaterDays;
  int consecutiveMissDays; // 每次打开App计算
  PlantStatus status;
  DateTime? bloomedAt;            // 开花（成功收获并移入成就花园）时间，仅 harvested 有值，展示“开花日期”（2.4）
}

enum PlantStatus { growing, stopped, dead, harvested }
```

WaterLog、AchievementRecord、MemorialPlant 模型保持不变。

### 4.3 JSON 文件

| 文件 | 路径 | 说明 |
| --- | --- | --- |
| seeds.json | assets/seeds.json | 种子配置（名称、周期、阈值、图片 asset 路径、稀有度等） |
| achievements.json | assets/achievements.json | 成就定义 |

## 9. 响应式设计规范（Responsive Design Spec）

### 9.1 断点与布局映射

```
width < 600        → phone      → Scaffold + BottomNavigationBar(3)
600 <= width < 840 → tablet-ish → Scaffold + 2-column Grid
width >= 840       → tablet     → Scaffold + NavigationRail + multi-column
```

### 9.2 页面级响应式规则

| 页面 | <600 | 600–839 | >=840 |
| --- | --- | --- | --- |
| 花园首页 | 单列卡片列表 | 2 列网格 | 左 Rail + 3 列网格 |
| 种子商店 | 横向类别 Tab + 单列 | 左类别 + 右 2 列 | 左类别 + 右 3 列 |
| 种植习惯 | 全屏表单 | 居中卡片（限宽 600） | 居中卡片（限宽 600） |
| 浇水页 | 全屏 | 居中 Modal | 居中 Modal |
| 开花庆祝 | 全屏 | 全屏 | 全屏 |
| 成就花园 | 单列网格 | 2 列 | 左列表 + 右多列 |
| 纪念花园 | 列表 | 2 列 | 3 列 |
| 设置页面 | 全屏列表 | 居中容器（maxWidth 600） | 居中容器（maxWidth 600） |
| 全局弹窗 | ✓ | ✓ | ✓ |

### 9.3 技术实现要点

- 使用 LayoutBuilder 读取 constraints.maxWidth，据此返回不同布局组件
- 避免在 widget 顶层使用 OrientationBuilder 切整页（方向≠宽度，横屏手机走窄布局）
- 弹窗 / 表单卡片使用 ConstrainedBox(maxWidth:600) 居中约束
- 状态保持：Riverpod 全局状态 + AutomaticKeepAlive 保活页面
